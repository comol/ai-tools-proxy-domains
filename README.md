# AI tools proxy domains

Списки хостов и масок Proxifier, чтобы гонять Cursor, Codex, Claude и соседние AI-сервисы через прокси **без полного VPN на всю машину**.

Два варианта:

1. **Точные домены** — узкий split-tunnel. Меньше побочек, легче дырки, если вендор завёл новый поддомен.
2. **Маски Proxifier** — «лучше перебдеть». Ловит служебные CDN/телеметрию, но `*google*`, `*github*`, `*microsoft.com*`, `*cloudflare*` и `*windowsupdate*` заворачивают уже почти всё подряд.

Схема, которая у автора масок работает без VPS:

- локальный прокси (у него это `127.0.0.1:8090`);
- Proxifier: AI-трафик в цепочку, localhost/Docker/системное — Direct;
- брандмауэр: исходящие у Cursor/Codex/VS Code/Antigravity **блокируются напрямую**, чтобы процесс не ушёл мимо прокси.

Оплата Cursor/Codex через эту схему у автора проходит. Адреса собирались агентом из открытых источников — **на полноту и точность никто не подписывается**. Дополняйте пулреквестами.

## Списки для роутера

9 октября 2026 добавлен список из конфигурации роутера, с которой, по сообщению пользователя, «вроде прокатило». Все 13 присланных доменов Cursor есть в секции Cursor файла [`hosts/exact-split-tunnel.txt`](hosts/exact-split-tunnel.txt); новым был `marketplace.cursorapi.com`.

Девять присланных IP-подсетей совпадают с IPv4-частью [официального списка Telegram](https://core.telegram.org/resources/cidr.txt) на дату добавления. Они сохранены отдельно в [`networks/telegram-ipv4-cidrs.txt`](networks/telegram-ipv4-cidrs.txt) для маршрутизации Telegram. Эти подсети не относятся к Cursor и не являются обязательным условием его работы.

Домены добавляйте в доменные правила роутера, CIDR-подсети — в IP-маршруты, если нужно направлять Telegram через тот же туннель. Строки с `#` и пустые строки — комментарии и разделители; при ручном импорте их пропускайте. Работа этой конфигурации на других роутерах не проверялась.
